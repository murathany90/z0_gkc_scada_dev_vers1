Kesin kural:
Bu sayfa docs dizininden çalışmayacak. HTML ve assets yalnız referans olarak kullanılacak.
Sayfa uygulamanın gerçek kaynak klasörlerine native React bileşeni olarak eklenecek.
Docs klasörü sonradan repodan kaldırıldığında yeni sayfa bozulmayacak.

Beklenen yerleşim:
- Sol menüde GKÇ İzleme bölümünde “Salınım Algılayıcı” menü öğesinin hemen altına yeni bir sayfa ekle.
- Yeni menü etiketi: “Salınım Eğitimi ve Simülasyon”.
- App state için yeni activeTab değeri kullan: örnek `oscillation_training`.
- `src/App.tsx` içinde bu activeTab için yeni sayfayı render et.
- Sayfa, mevcut `OscillationPage` içine gömülü ayrıntı sekmesi gibi değil, uygulama içinde ayrı native sayfa olarak çalışsın.

Native uygulama gereksinimleri:
- HTML dosyasını iframe, raw HTML injection veya `dangerouslySetInnerHTML` ile gömme.
- Kod React + TypeScript bileşenleri olarak yazılsın.
- CDN kullanılmasın.
- Chart.js eklenmesin.
- Uygulamada zaten `echarts` ve `echarts-for-react` var; grafikler için ECharts tercih edilsin.
- Eğer bazı eğitim simülasyonları canvas ile daha temiz olacaksa, React canvas bileşeni yazılabilir; yine de script tabanlı eski HTML mantığı doğrudan kopyalanmasın.
- Tema mevcut uygulama temasıyla uyumlu olsun: `themeMode`, `:root[data-theme="light"]`, CSS değişkenleri ve mevcut `card`, `btn`, `oscillation-*` desenleri dikkate alınsın.
- Türkçe karakterler kesinlikle bozulmasın. Kaynak dosyaları UTF-8 kaydet.

Simülasyon geliştirme gereksinimleri:
- `salinim_egitimi_ve_simulasyon.html` içindeki simülasyonlar temel alınabilir.
- `salinim_egitim_v2.html` içindeki PMU/FFT kayan pencere, damping, teşhis ve P-Q-V-f simülasyonları daha iyiyse ilgili kısımlar ondan modellenebilir.
- Eski HTML scriptlerini birebir taşımak yerine TypeScript pure fonksiyonlar yaz:
  - damped oscillation generator
  - P-Q-V-f scenario generator
  - sliding window segment selector
  - simple DFT/FFT amplitude estimator
  - BASTS/FBMSWA threshold decision generator
  - mode shape / DEF conceptual data generator
- Simülasyonlar deterministic olsun; random noise için seedli pseudo-random kullan.
- Aynı input aynı çıktıyı üretmeli, test edilebilir olmalı.

Kayan pencere simülasyonu:
- PMU Algılama sekmesinde geliştir.
- Kontroller:
  - pencere uzunluğu
  - adım/pencere konumu
  - gürültü seviyesi
  - hedef mod frekansı
- Grafikler:
  - ham sinyal zaman grafiği
  - aktif pencere vurgusu
  - FFT/DFT spektrum çıktısı
  - mümkünse spektrogram benzeri zaman-frekans ısı haritası
- Aktif pencere görsel olarak mavi/yarı saydam alanla belirtilsin.
- Spektrumda hedef mod frekansı dikey işaret veya marker ile gösterilsin.
- Altında operatör yorumu üret:
  “Aktif pencere 0.35 Hz civarında baskın bir bileşen gösteriyor; bu bant bölgeler arası salınım adayıdır.”

P-Q-V-f simülasyonu:
- Dört metriği birlikte göster:
  - Frekans f (Hz)
  - Aktif Güç P (MW)
  - Gerilim V (kV veya p.u.; seçilen birimi açık yaz)
  - Reaktif Güç Q (MVAr)
- Senaryo seçimi:
  - Bölgeler arası
  - Lokal
  - Zorlanmış
- Şiddet/genlik slider’ı olsun.
- Olay başlangıcı dikey marker ile gösterilsin.
- Altında kısa tablo:
  - baskın frekans
  - beklenen mod
  - genlik etkisi
  - operatör yorumu

Salınım modları sekmesi:
- Mod seçimi için segmented buttons kullan.
- Her mod için zaman alanı grafiği ve frekans bandı görselleştirmesi olsun.
- Modlar:
  - Interarea / Bölgeler arası: yaklaşık 0.1-0.8 Hz
  - Local / Yerel: yaklaşık 0.8-2 Hz
  - Forced / Zorlanmış: frekansı kaynağa bağlı
  - Torsional / SSO: daha yüksek frekans bandı, uygulamada diagnostik anlatım
  - IBR kontrol etkileşimi: evirici/PLL/kontrol kaynaklı kavramsal anlatım
- UI metni operatör dilinde olsun; akademik paragraflar kısa tutulmalı.

Sönümleme ve enerji sekmesi:
- Damping ratio slider’ı olsun.
- Negatif, sıfıra yakın, zayıf pozitif ve güvenli damping durumları ayrı yorumlansın.
- Grafik:
  - salınım sinyali
  - üst/alt zarf
  - enerji göstergesi
- Kritik durumlarda kırmızı uyarı kutusu göster:
  “Negatif damping, büyüyen salınım eğilimi anlamına gelir.”

BASTS / FBMSWA sekmesi:
- Çift pencere mantığını anlat:
  - kısa pencere: hızlı genlik tespiti
  - uzun pencere: faz/yön doğrulama
- Simülasyon kontrolleri:
  - genlik eşiği
  - faz açısı
  - tetikleme/kapanma eşikleri
- Karar çıktısı:
  - Normal kip
  - Bekleme/histerezis
  - Kapasitif kip
  - Endüktif kip
- Canlı sisteme komut gönderiyormuş gibi görünmesin; “eğitim simülasyonu” olduğu açık ama ürün dışı taslak dili olmadan belirtilsin.

Vaka ve teşhis sekmesi:
- Mode shape ve kaynak lokalizasyonu kavramsal gösterilsin.
- 6 PMU örneği ile faz/genlik deseni çiz.
- DEF benzeri bar grafikte kaynak/soğurucu ayrımı yap.
- Örnek olay yorumu üret:
  “Karşı fazlı iki PMU grubu ve düşük frekans bandı, bölgeler arası salınım karakterine işaret eder.”

Karar Destek sekmesi:
- Salınım Algılayıcı rapor ekranındaki karar destek diline uyumlu olsun.
- Ham log dili kullanma.
- Tablo + yorum formatı kullan.
- Örnek açıklamalar:
  - “0.35 Hz bandındaki bileşen bölgeler arası mod adayıdır.”
  - “Damping oranı düşükse olay izleme seviyesinde tutulmalıdır.”
  - “Negatif damping görülürse büyüyen salınım riski vurgulanmalıdır.”
- Eğitim amaçlı olduğunu söyle, ama “taslak/doküman referansı” dili kullanma.
